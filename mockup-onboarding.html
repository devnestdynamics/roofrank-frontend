Onboarding redesign mockup — analyst-led

Current cold-signup flow ("Welcome → personalize → score your first deal") is generic SaaS copy that doesn't say what the product does. Proposed redesign drops to 3 steps, uses the analyst voice + dashboard visual language, and demonstrates value (real deals in their markets) before asking for more input. Below: the 3 proposed steps stacked, plus a quick before/after of step 1 so you can feel the tone shift.

Step 1 — Pick markets replaces "Welcome / personalize"

Current step 1 collects First Name + Email — but they JUST typed email on signup, so we're asking twice. Proposed step 1 is functional: pick markets, filter the feed. First name moves to optional later (or comes from Stripe if they pay). Email isn't re-asked at all.

What changed: H1 swaps from "Welcome to RoofRank" (generic) to "Where are you hunting?" (action verb, addresses the user as someone with intent). Sub-copy says what the analyst does ("scores every 2-6 unit listing in these cities every night") instead of generic "personalize." Each city chip shows live active-deal count — concrete, demonstrates the inventory is real. Selected by default: zero markets, user picks at least one. Doesn't ask for name/email — we have those from signup.

Step 2 — Live deal preview replaces "Score your first deal"

Current step 2 asks "paste an address you're looking at" — but a brand-new user typically doesn't have one. Proposed step 2 shows them what the product DOES: 1 hero deal + 2 runners from their picked markets, with analyst quote. Demonstrates value before any more inputs. Zero forms.

Why this works: instead of an empty form asking for input, the new user sees REAL deals in markets they just picked — with the analyst's voice quoted inline. Communicates the value prop ("AI analyst that scores every multifamily listing") through demonstration, not copy. Bonus: when ATTOM is down, this step pulls from the existing /api/feed/public endpoint which doesn't need ATTOM to fetch scored deals (they were scored at ingest time).

Implementation note: reuses the existing public-feed API + deal-row visual primitives. No new infra. ~1 day frontend.

Step 3 — Optional SMS phone new · skippable

Lays the groundwork for Twilio (#222) without forcing it. Skippable — they can add later from account settings. Frames SMS as "we'll text you when something matches" rather than "give us your number."

Strong Buy alerts only. Not your standard daily newsletter — these only fire when a deal scores 75+ in your markets.
Price drops on watched deals. If a deal you saved cuts the price, you'll know first.
Reply STOP to opt out. Standard messaging rates apply. No marketing spam.
You can add or remove this anytime from account settings.

Why optional + skippable: SMS opt-in friction loses 20-40% of cold signups if mandatory. Making it the 3rd-of-3 step + clearly skippable means we capture phone numbers from the users most likely to actually want alerts (real intent), while not blocking the rest from reaching the dashboard. Sets up Twilio (#222) for an immediate-value debut — the first Strong Buy alert is the user's first real "wow" moment.

Copy choices: "your analyst finds one" reinforces the analyst persona. "Strong Buy alerts only" is the value commitment — no daily noise. "Reply STOP" + "Standard messaging rates" pre-empts TCPA concerns and sets correct expectations.

What ships when this is approved

Engineering scope assuming green-light on this direction.

Frontend (~3-4 days):
· Rewrite roofrank-onboarding.html with the new 3-step flow. Keep file name + URL.
· Step 1 calls existing POST /api/feed/markets to save the user's market picks (already wired)
· Step 2 calls existing GET /api/feed/public (no new endpoint needed — same one the landing page uses)
· Step 3 saves the phone number to user.phone (new column on users table — small migration)

Backend (~½ day):
· Migration to add phone column to users table
· POST /api/auth/me/phone (validate US format, save) — Twilio integration comes later under #222

Hard prerequisite: none. Works in degraded mode (no live counts) if ATTOM is still 401'd; the active-deal counts on each market chip read from rentcast-source rows that don't need ATTOM.

Migration: existing onboarding users mid-flow when this lands have nothing to lose — they just see the new flow on next sign-in. No data loss.

Don't ship until: the analyst-led positioning rewrite (#223) is approved, since this onboarding leans heavily into the "analyst" voice and would feel inconsistent with the rest of the product if positioning stayed generic.
