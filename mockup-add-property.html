Add a property — backlog #220 mockup

Replaces the existing roofrank-analyzer.html with a much-lower-friction flow. Same end goal (score a property not on our feed), but RentCast + ATTOM auto-fill 90% of the form so the user just supplies the asking price. Below: the 4 user-facing states, in order. Last panel shows where saved analyses live (the new My Deals tab — replaces the killed roofrank-reports.html).

Step 1Empty state — enter an address

Single input. No form to fill, no checkboxes, no "select property type" pre-flight. Paste the address, hit Look up, we do the heavy lifting.

Paste an address. I'll pull what's public, you give me the asking price, and I'll score it against the same model that runs every deal in your feed. Saves to your private My Deals tab — not visible to other users.

Works on any US residential address. Best results in our MA launch markets (Lynn, Worcester, Salem, Revere, Framingham), but the scoring model runs anywhere. Pro plan: 5 added properties per month. Team: 50/month.
What happens when you click Look up
1I check RentCast property records for year built, square footage, bedrooms, lot size — usually all populated.
2I run ATTOM enrichment for unit count, neighborhood grade, and assessor tax. This is the only field that sometimes fails — I'll flag if so and let you input manually.
3You add the asking price (FSBO listings, off-market leads, etc. — public records don't have this).
4I score it using the same model your feed uses, with today's Freddie rate. Saves to My Deals when you're done.

Why this is better than the current analyzer: the old form had 8 fields (address, asking, rent, beds, baths, sqft, year built, units) — most of which RentCast already knows. Users abandoned the form. With auto-fill, the user goes from zero to scored deal in 2 inputs instead of 8.

Step 2Lookup complete — confirm + add asking price

After ~2-3 seconds the auto-fill lands. Provenance is visible per field — user can tell what came from RentCast vs ATTOM vs them. Only the asking price field is required from the user (everything else is editable but defaults to the pull).

Provenance is the key trust signal here. Every field is labeled with where it came from (RentCast, ATTOM, or "you provide"). User can edit anything if they have better info — but the defaults are explicit measurements, not guesses. Required-field-only highlight: asking price gets the forest border + sage tint so it's the first place the user's eye lands.

What happens when ATTOM fails to classify (the 401 case + the "ATTOM didn't classify this building" case): the Units + Neighborhood Grade fields go into manual-input mode with a warning strip. User picks Duplex/Triplex/etc. from a dropdown. Score still runs; provenance flag flips to "user-input" so we can audit if they self-classify wrong later.

Step 4Where saved analyses live — the My Deals tab

Replaces the killed "My Reports" page. Lives as a tab on the dashboard rather than a separate sidebar surface. Three reasons: keeps the user in the feed context, eliminates a sidebar item, and uses the exact same deal-row shape as Today and Watching (zero new UI primitives).

Why a tab instead of a page: "My Reports" was a dead-end surface that pulled users out of the deal context. Putting saved analyses INSIDE the dashboard as a 3rd tab keeps the user one tap away from cross-comparing their off-market finds against the live MLS feed. It also kills a sidebar item and a redundant quota system.

What stays on the deal card itself: small private-tag badge ("Off-market" / "FSBO" / "Manual") makes it clear at a glance that these aren't MLS-sourced deals. Otherwise the row is visually identical to a Watching row — same rmark, same verdict, same cashflow display. Maximum reuse.
